Research brief

What the reference course actually teaches

Before designing anything, I looked at what IndyDevDan — an independent engineer-educator with 15+ years of production experience and a YouTube channel built around Claude Code and agentic workflows — actually ships in his paid curriculum, Tactical Agentic Coding (bundled with its prerequisite, Principled AI Coding).

Findings, official source only

Shape
14 lessons total: an 8-lesson core progressing beginner → intermediate → advanced, plus a 6-lesson "Agentic Horizon" extension. ~12.5 hrs of video across both courses.
Core framework
"The Big Three" — Context, Prompt, Model — taught as the three levers that turn prompting from guesswork into precision.
Signature ideas
The 12 Leverage Points; AFK Agents (autonomous, not "in the loop"); Closed Loop Prompts (agents that validate their own output); Zero-Touch Engineering as the stated end-state; multi-agent orchestration via a single orchestrator.
Gate
Explicitly "not for beginners" — targets mid/senior engineers already shipping production code.
Philosophy
"Principles, not tools." Teach concepts that outlive whichever model or CLI is current.

Everything above is publicly described on the creator's own site — I did not access, purchase, or reproduce any paid lesson content. Several search results were course-piracy resale sites; those are excluded on purpose.

Design rationale

What's borrowed, what's original

The reference course's pedagogical shape is worth keeping: a hard skill gate, a small set of named principles taught before any tool, a progression from concrete to autonomous, and a capstone that has to run on real code, not a toy. That shape is sound regardless of who teaches it.

What follows below does not reuse his proprietary terms or lesson content. It's a separate curriculum, "Agent Operations," with its own framework and module set, aimed at the same transition — engineer to agent operator — built from first principles rather than from his course transcript.

Core framework

The Four Dials

Every lesson in this curriculum comes back to one of four things an operator adjusts. Nothing else is tunable — an agent that's failing is failing because one of these four is wrong.

F

Feed

What the agent can see: files, docs, prior runs, constraints. Most failures are starvation, not stupidity.

F

Frame

The spec you hand it: scope, done-criteria, and what's explicitly out of bounds.

F

Fit

Which model and which tools for this task — not the biggest, the right one.

C

Check

How the work is verified before a human ever looks at it — tests, lint, a second agent, a rubric.

Entry gate

Who this is for

Same bar as the reference course, for the same reason: teaching delegation to someone who can't yet do the work themselves produces engineers who trust agents they can't evaluate. Prerequisites: 2+ years shipping production code, comfortable in a shell, has used any AI coding tool at least casually, owns a real codebase (personal or work) to run the capstone against.

Curriculum

Four tiers, eleven modules

Tier 0

Orientation

One module. The mindset shift, before any tooling — most people skip this and pay for it in Tier 2.

0.1

You Are No Longer the Typist

Lecture · 25 min

Reframes the job: from producing code to producing the conditions under which an agent produces correct code. Covers why "just prompt better" plateaus, and what replaces it.

Done when: you can name, for your last week of work, which parts were typing and which were judgment.

Tier 1 · Foundations

Running One Agent Well

Concrete, hands-on, single agent, full supervision. Every lesson ships a working artifact.

1.1

First Real Task, End to End

Lab · 45 min

Take one real (not toy) ticket from your own backlog through an agent from spec to merged diff, narrating every decision point out loud.

Artifact: a merged PR plus a one-page log of every correction you made and why.

1.2

Feed and Frame

Lecture + Lab · 60 min

The first two dials in depth: what context actually moves the needle (file selection beats prompt length), and how to write a frame with unambiguous done-criteria.

Artifact: a reusable task-frame template you'll use for the rest of the course.

1.3

Reading a Failure

Lab · 40 min

A catalog of the five ways agent output fails silently — confident wrong answers, scope creep, invisible assumptions, stale context, and over-eager cleanup — with a diagnostic pass for each.

Done when: given a broken diff you've never seen, you can name which of the five it is in under a minute.

Tier 2 · Practice

Making the Agent Check Itself

Specs, verification loops, and tool access — the agent starts doing more without you watching every step.

2.1

Spec Before Code

Lecture + Lab · 50 min

Writing a spec the agent can be graded against — testable invariants, not vibes — and using it as the frame for a multi-file change.

Artifact: a spec + implementation for a feature with 3+ non-obvious edge cases.

2.2

The Fit Dial

Lecture · 35 min

Model and tool selection as a real engineering decision: cost, latency, and failure-mode tradeoffs across a cheap/fast model, a strong reasoner, and a specialized tool call.

Done when: you can justify, in one sentence, why a task got the model it got.

2.3

Closing the Loop

Lab · 55 min

Wiring the Check dial into the workflow itself: tests-first hand-off, an agent that runs its own lint/typecheck/test cycle, and a second agent that reviews the first's diff before you do.

Artifact: a task that completes with zero manual test-running on your part.

Tier 3 · Autonomy

Running the Fleet

Standards encoded as artifacts, agents running without a babysitter, and more than one agent at a time.

3.1

Encode, Don't Repeat

Lab · 45 min

Turning the corrections you've been making by hand since Tier 1 into a standing artifact — a house style doc, a reusable reviewer persona, a lint rule — so the agent stops making the same mistake.

Artifact: one encoded standard that measurably reduces your correction rate on the next 5 tasks.

3.2

Working Without a Babysitter

Lecture + Lab · 60 min

Designing a task an agent can run unattended: checkpoints instead of continuous supervision, a rollback path, and a hard stop condition it can't talk itself past.

Artifact: an unattended run with a checkpoint log you review after the fact, not during.

3.3

One Operator, Several Agents

Lab · 60 min

Splitting a task across specialist agents (a finder, an implementer, a reviewer) under one orchestrator, and reading a fan-out/fan-in result without reading every sub-agent's transcript.

Artifact: a 3+ agent pipeline on a task too broad for one agent to hold in context.

3.4

Measuring the Operator, Not the Agent

Lecture · 30 min

The four numbers that tell you whether delegation is actually working, and why "lines of code shipped" isn't one of them.

Done when: you have a personal baseline for all four, from your own last two weeks of work.

The Standing Pipeline

Take one recurring task from your actual job — not invented for class — and build a pipeline that runs it with minimal touch: spec template, model/tool selection, a self-check loop, an encoded standard, and a rollback path. Run it for two real cycles before presenting.

Reviewed against the rubric below by a peer who has never seen the pipeline before — if they can't tell what it did without asking you, it's not done.
